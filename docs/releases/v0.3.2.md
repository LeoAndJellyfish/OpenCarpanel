# OpenCarpanel v0.3.2 — Dashboard Controls & Update Progress

`v0.3.2` 让两条高频操作变得可见且可预期：仪表盘组件现在像 Steam 浮层一样通过侧栏开关启用或停用，桌面端安装更新时则会持续显示真实下载进度与当前阶段。游戏遥测、配对、局域网传输和布局文件格式保持兼容。

## 仪表盘编辑器

- “添加组件”改为即时组件开关；单击已启用组件会停用，单击未启用组件会在全部响应式断点中恢复它。
- F1 24 / F1 25 只显示方程式赛车适用组件，包括 Race 与 Tyres & damage；ETS2 / ATS 只显示卡车适用的 Route & job。
- 挡位、速度、转速和连接状态作为公共组件在四款游戏中保留。
- 开关状态使用边框、滑块、文字和 `aria-pressed` 共同表达，支持键盘操作，不只依赖颜色。
- 导入布局中的重复组件仍可保留并单独编辑；侧栏会显示实例数量，停用时一次移除该类型，避免残留造成开关状态含糊。
- 画布检查器的“移除”继续提供单实例删除；删除后可从侧栏再次启用。

## 应用内更新进度

- 点击安装后立即显示准备、下载、验签和安装阶段，不再只停留在不可观察的等待状态。
- 更新器有总大小时显示真实百分比与“已下载 / 总大小”；服务器未提供总大小时显示不定进度，不伪造百分比或剩余时间。
- 进度通过 Tauri IPC Channel 从 Rust updater 直接传到桌面 Preact 界面，不需要轮询或远程服务。
- 下载或签名失败不会停止 Host，也不会替换当前版本；只有验签成功后才进入既有安装流程。
- 动画只更新合成友好的 `transform`，并在 `prefers-reduced-motion` 下改为静态反馈。

## 兼容性与升级

- 可从 v0.3.1 直接升级；Host 配置、游戏目录、已配对设备和每游戏独立布局保持不变。
- Dashboard 布局 schema、Widget manifest schema、Host API 与导入导出 JSON 均未升级。
- 旧布局中存在不适用于当前游戏的组件时不会被静默删除，仍可在画布中选择和处理；新组件侧栏只提供当前游戏有数据来源的内置组件。
- 本版本继续支持 F1 24、F1 25 原始 2025 模式、F1 25 2026 Season Pack、ETS2 与 ATS。

## 验证

- Desktop、Dashboard 与 Widget SDK 严格 TypeScript 检查通过；60 项 Web 测试通过。
- 新测试覆盖四款游戏的组件集合、按类型移除重复实例，以及每个默认组件在四个断点关闭后重新启用。
- 真实 Chromium 演示模式验证 F1 → ETS2 切换、侧栏停用、检查器移除和重新启用，状态与画布同步更新。
- Rust workspace fmt、Clippy `-D warnings`、全量测试、Host 发布包与多游戏 smoke test 由本地门禁和 Release 工作流共同执行。
- Release 工作流继续生成 Windows x64 NSIS/MSI、macOS Apple Silicon/Intel DMG 与签名更新包；只有资产矩阵和 `latest.json` 全部核验后才公开 Release。

## 安装与已知边界

- Windows x64 优先下载 NSIS `setup.exe`；Apple Silicon 与 Intel Mac 分别下载对应架构 DMG。
- 安装程序尚未使用 Windows Authenticode 或 Apple Developer ID/notarization，因此本版本仍为 public preview。
- 真实游戏、干净操作系统、手机/iPad 长时帧率和端到端延迟验收继续记录在[发布检查清单](../release-checklist.md)。
