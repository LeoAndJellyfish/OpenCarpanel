# F1 25 UDP 适配器资料与边界

## 权威资料

- [EA SPORTS F1 25: 2026 Season Pack UDP Specification](https://forums.ea.com/blog/f1-games-game-info-hub-en/ea-sports%E2%84%A2-f1%C2%AE25-2026-season-pack-udp-specification/12187347)
- 核验日期：2026-08-12
- 实现基线：EA 页面提供的原始 F1 25 v3 与 2026 Season Pack v10.0 两份附件。

EA 同时保留原始 F1 25 与 2026 Season Pack 两种 UDP mode。OpenCarpanel 用同一个稳定 adapter ID `f1-25` 接受 packet format `2025` 和 `2026`；Dashboard 的游戏身份与用户布局不会因用户切换这两个 mode 而改变。

## 精确 wire layout

两种格式都使用 29 字节 packed、小端公共头，并从头部的 `packetFormat` 选择不可变布局：

| UDP mode | format | packet id/version | 车辆数 | 单车长度 | 总包长 |
| --- | ---: | --- | ---: | ---: | ---: |
| F1 25 original | `2025` | `6 / 1` | 22 | 60 bytes | 1352 bytes |
| 2026 Season Pack | `2026` | `6 / 1` | 24 | 59 bytes | 1448 bytes |

2026 把车辆上限从 22 提高到 24，并把 Car Telemetry entry 中的发动机温度由 `uint16` 改为 `uint8`，因此每车减少 1 byte。驾驶页所需字段都位于每车 entry 的前 20 bytes，偏移在两套结构中保持一致：

| entry offset | wire type | 映射字段 |
| ---: | --- | --- |
| `0` | `u16` | speed，km/h → m/s |
| `2` | `f32` | throttle |
| `10` | `f32` | brake |
| `15` | `i8` | gear |
| `16` | `u16` | engine RPM |
| `18` | `u8` | DRS |
| `19` | `u8` | rev lights percent |

decoder 先验证公共头、format、packet id/version、精确总长和 `playerCarIndex`，再使用该 format 的车辆数与 stride 定位玩家车辆。解析逐字段读取，不进行 Rust 结构体内存映射，不使用 `unsafe`；有限浮点、0–1 比例与枚举也会校验。错误长度不会按另一格式试读。

## 当前输出

- 速度、档位、RPM、转速灯百分比、油门、刹车和 DRS。
- session UID、overall frame ID 与逻辑 `gameId = f1-25`。
- 原始 2025 与 2026 Season Pack 进入同一 canonical telemetry schema。

## 明确未支持

- 2026 新增的 Car Telemetry 2 packet（packet id `16`）及其中的主动空气动力学等新字段。
- 圈速、比赛位置、session、轮胎、损伤、天气、处罚与赛事事件 packet。
- 从 format `2024`、未知年份或未知 packet version 推断兼容。

F1 24 与 F1 25 共享安全 cursor 与已验证字段代码，但 F1 24 只接受 `2024`；F1 25 只接受显式列出的 `[2025, 2026]`。交叉拒绝与精确包长测试防止相近年份被误识别。
