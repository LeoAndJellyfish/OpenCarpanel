# 仪表盘组件开关设计

## 目标

仪表盘编辑器的组件侧栏改为类似 Steam 浮层的开关列表。用户单击组件即可启用或停用，不再需要先理解“添加”和画布选中后的隐藏删除入口。列表必须随当前游戏变化，只呈现该游戏能够提供数据的组件。

## 方案取舍

评估了三种实现：继续使用添加按钮并强化错误提示、把组件拖入画布、使用即时开关。添加按钮仍会把已存在组件误解为可重复添加；拖放在手机和平板上不够可靠，也没有解决游戏适用性问题。即时开关与现有自动布局、多断点文档模型最契合，因此作为本次方案。

组件适用性保留在 Dashboard 内置目录中，以明确的游戏 ID 映射表达，不扩张公开 Widget SDK 的清单协议。F1 24 和 F1 25 使用方程式组件集合，ETS2 和 ATS 使用卡车组件集合；公共的挡位、速度、转速和状态组件在两类游戏中都可用。

## 交互

```text
当前游戏
   ↓
过滤内置组件目录
   ↓
┌─────────────────────────────┐
│ Speed       已启用      ●━━ │  单击 → 停用该类型
│ Race        未启用      ━━● │  单击 → 在全部断点添加
└─────────────────────────────┘
```

- 组件项使用按钮和 `aria-pressed`，支持键盘与辅助技术。
- 开启状态通过边框、轻量底色和滑块共同表达，不只依赖颜色。
- 停用时移除该类型的全部实例，使侧栏的二态语义确定；画布检查器继续提供单实例删除，兼容导入的重复组件布局。
- 启用时沿用确定性的多断点空位查找。正常的关闭后重开会复用释放出的容量；自定义布局确实已满时显示明确提示，不产生只在部分设备出现的组件。

## 数据与兼容性

布局 JSON、Host API、导入导出格式和 Widget SDK 均不变。现有布局可直接加载；如果旧布局含有重复实例，侧栏显示实例数量，停用动作会一次关闭该组件类型。切换游戏时重新计算目录和启用状态，不共享不同游戏的布局。

## 验证

- 单元测试覆盖四款游戏的组件集合，防止 F1 出现路线组件或卡车出现比赛、轮胎组件。
- 文档编辑测试覆盖按类型移除全部实例，同时保留其他组件。
- 对每个默认布局验证组件停用后可以重新启用，并在所有断点获得有效位置。
- 执行 Dashboard 类型检查、单元测试和生产构建，并在浏览器演示模式中验证单击、键盘及游戏切换行为。
