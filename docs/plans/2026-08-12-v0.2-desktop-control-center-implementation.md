# OpenCarpanel v0.2.0 桌面控制中心实施计划

## 目标

交付 Windows/macOS Tauri 2 桌面控制中心，同时保留独立 `opencarpanel-host` CLI；GUI/CLI 共享唯一 Host 核心、设置、设备与实例锁。发布 GitHub Release、签名 updater artifact 和 `latest.json`，手机 Dashboard 架构保持兼容。

## 工作分解

### 1. 共享应用核心

- [x] 在 `apps/host` 增加用户级 `InstanceGuard`、结构化持有者信息和独立测试 override。
- [x] CLI 在 bind 前获取 guard；加载 `settings.json` 后再应用显式 env override。
- [x] `crates/config` 增加 `SettingsRepository`、原子写、三份备份、损坏隔离和兼容测试。
- [x] Host 暴露脱敏 `HostDiagnostics`、QR SVG、设备列表/撤销和受监督 shutdown。
- [x] 把设备 session digest 与元数据持久化到 `clients.json`；协议以可选字段携带设备名称。
- [x] 把 snapshot Hz 上限真正应用到 WebSocket publication。

### 2. Tauri 桌面壳

- [x] 创建 `apps/desktop` Preact/Vite 与 `src-tauri` workspace member。
- [x] 在 Tauri setup 获取共享 guard、加载设置并直接 `bind_host`；不 spawn CLI。
- [x] 实现最小 commands：bootstrap/status、pairing、devices、settings/restart、SCS、dashboard、logs、system、update。
- [x] 实现主窗口 close-to-tray、托盘 show/dashboard/pair/quit 和显式优雅退出。
- [x] 实现日志滚动、Host 状态采样与游戏连接/断开通知。

### 3. Pit Wall Control Room UI

- [x] 总览链路、动态游戏信号色、数据龄与包计数。
- [x] 二维码配对和设备管理。
- [x] F1 设置说明与 SCS 插件检查/安装向导。
- [x] Dashboard 驾驶页/编辑器入口。
- [x] 网络、adapter 和发布频率表单；保存时展示重启/回滚结果。
- [x] 托盘、开机启动、通知和更新偏好。
- [x] 诊断摘要、完整脱敏 JSON 与日志目录入口。
- [x] 键盘、对比度、窄窗口和 reduced-motion 验证。

### 4. 分发与更新

- [x] 生成项目图标集；包内加入 CLI、SCS plugin、LICENSE/NOTICE/docs。
- [x] Windows 生成 NSIS/MSI；macOS 生成 x64、arm64 DMG/app/updater artifact。
- [x] 创建 updater key，公钥入配置，私钥/密码只写 GitHub secrets。
- [x] `tauri-action` 在 tag 上构建、签名 artifact、汇总并验证 `latest.json`。
- [x] 未有平台证书时采用明确的 preview 文案；macOS 使用 ad-hoc identity 并记录 Gatekeeper 限制。

### 5. 验证与发布

- [x] Rust fmt/Clippy/tests，Web type/test/build，SCS native tests。
- [x] 二次启动、GUI↔CLI、端口被第三方占用集成测试。
- [x] 设置坏文件恢复、设备 revoke、SCS 安装备份、诊断脱敏测试。
- [x] Windows 本机 Tauri production build、嵌入 Host 与安装清单 smoke。
- [x] CI Windows/macOS 构建；bundle 前强制 staging GUI、CLI、SCS/许可资源，公开 Windows updater 使用编译内公钥独立验签。
- [ ] 在 Windows、Apple Silicon 与 Intel Mac 干净环境分别下载安装包，核对安装后的 GUI、CLI、资源和 OS 行为。
- [x] 更新 `README`、快速开始、发布清单与 `v0.2.0` release notes。
- [x] 提交、push、tag `v0.2.0`，等待 CI/Release 全部成功并验证 Latest。

## 提交边界

1. `docs: accept the v0.2 desktop architecture`
2. `feat(core): share settings devices and instance ownership`
3. `feat(desktop): add the Tauri control center`
4. `feat(desktop): add setup system and update workflows`
5. `release: ship OpenCarpanel v0.2.0`

每个边界必须在提交前通过其相关的最小测试；最终发布前执行完整门禁，不能把真实平台未验项目自动勾选。
